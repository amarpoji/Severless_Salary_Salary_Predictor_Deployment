


# 💰 Serverless Salary Predictor

A full-stack Machine Learning application deployed as a Serverless Microservice on AWS. 
This project serves a Linear Regression model via a FastAPI backend, containerized with Docker, and hosted on AWS Lambda behind an API Gateway.

## 🏗️ Architecture
The project follows a cloud-native architecture:
1.  **Model:** Scikit-Learn Linear Regression (trained on dummy data).
2.  **API:** FastAPI (Python) handles the request logic.
3.  **Container:** Docker packages the OS, dependencies, and model.
4.  **Cloud:**
    * **AWS ECR:** Stores the Docker Image.
    * **AWS Lambda:** executes the code on-demand (Serverless).
    * **AWS API Gateway:** Provides the public HTTP endpoint.

## 🚀 How to Run Locally

1.  **Train the Model**

    ```bash
    python train.py
    ```

2.  **Build the Docker Container**

    ```bash
    docker build -t salary-predictor .
    ```

3.  **Run the Container**

    ```bash
    docker run -p 9000:8080 salary-predictor
    ```

## ☁️ Deployment Guide (AWS)

### Prerequisites

  * AWS CLI installed and configured.
  * Docker Desktop running.

### 1\. Create ECR Repository

Create a repository named `salary-predictor` in AWS Elastic Container Registry (ECR).

### 2\. Login to ECR

```bash
aws ecr get-login-password --region YOUR_REGION | docker login --username AWS --password-stdin YOUR_ACCOUNT_ID.dkr.ecr.YOUR_REGION.amazonaws.com
```

### 3\. Build & Push Image

*Note: The `--provenance=false` flag is required for AWS Lambda compatibility on newer Docker versions.*

```bash
# Build
docker build --provenance=false -t salary-predictor .

# Tag (Replace URI with your ECR URI)
docker tag salary-predictor:latest YOUR_ECR_URI:latest

# Push
docker push YOUR_ECR_URI:latest
```

### 4\. Create Lambda Function

  * Create a function from **Container Image**.
  * Select the image pushed to ECR.
  * **Configuration:** Increase Memory to `512MB` and Timeout to `30s`.

### 5\. Setup API Gateway

  * Create an **HTTP API**.
  * **Routes:** Create two routes to handle traffic correctly:
      * `ANY /` (For the homepage)
      * `ANY /{proxy+}` (For the API endpoints)
  * Attach the Lambda integration to both routes.
